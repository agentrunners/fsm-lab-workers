### The brief's focus questions — answered from the code

- **Dedup window (the ">300s delayed report" walk):** NO, a delayed legitimate report cannot be deduped away. (1) `dedup_window: 300` (lib/fsm.mjs:119) counts **event-id entries**, not seconds — `pushDedup` keeps the last 300 keys (lib/fsm.mjs:414-416). (2) Dedup keys are per-delivery event identities `rep-<runId>-a<attempt>` (lib/event-ingest.mjs:82-86, minted once per worker turn at worker/turn.mjs:395) — a first-delivery delayed report is by construction not in the ring. (3) A *redelivered* id that fell out of the 300-entry ring falls through to the lease gates — `task-not-leased(...)` or `stale-lease` (lib/fsm.mjs:223-227) — REJECTED and journaled (lib/fsm.mjs:384-398), never double-applied. (4) "Stuck in-flight forever" is structurally impossible: the clock's lease-timeout pass (lib/fsm.mjs:489-504) requeues or quarantines on expiry regardless of reports; a worker whose report never enqueued (worker/turn.mjs:400-412, hardened retry ×2 over the store's 8 CAS attempts) exits 2 with a step-summary remedy, and the reaper backstops. The real delayed-report hazard is **stale-lease attempt burn** (at-least-once by design, visible in `orphaned_reports`) — amplified by A4-F1 when the lease is shorter than the work.
- **The AR probe rejection path / ingest doors:** verified. The ONLY machine-plane ingest doors are the three CAS queues on fsm-state (report: lib/store.mjs:497-523; control: 375-401; intake: 460-488) plus direct `fsm-control` dispatch (write-class, strict-routed). A foreign worker's report line is drained and rejected `unknown-task` at lib/fsm.mjs:222 — exactly the 20-e live probe's observed outcome; the rejection is journaled (A4-class audit trail), nothing applied. The legacy `fsm-report` dispatch lane routes but no workflow registers the type (lib/event-ingest.mjs:132-139) — dead, kept for shape strictness.
- **Malformed genesisSpec wedging an epoch at birth:** the door's validation is complete enough that no *door-passing* spec can wedge genesis (all keys validated; mode pinned to a 3-value vocabulary; id git-ref-valid; artifacts bound + capped). The one wedge path is the vocabulary *drift* between the door's twin lists and the core's (A4-F6) — unpinned today.
- **task-pr recovery:** yes, recovery paths exist and are pinned: open-PR reuse (lib/task-pr.mjs:108-110), merged/closed 422 fold (124-131), PAT-on-403-only ladder (120-122), raced-twin no-op stamp (147-149), deferred/cap alerts (176-203), the quiesced-path drain that gives a halted epoch its only retry (conductor/turn.mjs:311-337), and the pre-rollover candidate capture (lib/conductor-core.mjs:622-629 + store.mjs:251/325 pass-through). Residuals: A4-F3 (comment loss), A4-F10 (alert flood), and the documented rollover-stamp noop (links ride the completion comment only — conductor/turn.mjs:500-509).

## §3 The 3 findings that most block production-grade

1. **A4-F1 — the spec's `lease_minutes` is advertised, validated, and then silently dropped at genesis** (lib/intake.mjs:411 vs lib/conductor-core.mjs:637-639 / conductor/turn.mjs:196-216): the single most consequential human-plane contract break — long CC tasks get reaped, duplicated, and degraded-halted through a knob the system told the user works. Effort S, closes the "9-min grind" class.
2. **A4-F3 — the completion digest / PR-links comment to the intake issue is one fire-and-forget POST with no retry and a green run** (conductor/turn.mjs:510-511): the loop's human-side closure (issue → epoch → PRs → completion) can silently break on one transient API failure, orphaning the notification AND the PR-link digest permanently.
3. **A4-F2 — no per-task operator verb anywhere on the console/ops surface** (ops/turn.mjs:20, ops/console.mjs:50): incident response for a single wedged task is impossible without epoch-wide `reset`; the FSM's own cancelled edges are unreachable by any control.

## §4 What is already production-grade (honest inventory)
