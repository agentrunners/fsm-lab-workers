## §3 The 3 findings that most block production-grade

1. **W1 — the cc key-pool failover is unreachable at the dispatched budget** (cc-adapter.mjs:125-131 × conductor-core.mjs:145): with the deployed chain, `OPENROUTER_API_KEY_2` can never serve a lane, so the designed answer to key-death (rotate to key 2) does not exist and a drained primary quarantines every cc task through infra-exhaustion. Capacity/redundancy is documented but not enforced — the single biggest gap to "production-grade" in this lens.
2. **W4 — the E11 marker heuristic can quarantine good work** (worker-contract.mjs:498-503 via turn.mjs:480): any done whose result text merely CONTAINS 'rate limit'/'unauthorized'/… is reclassified infra and net-zero-retried into `infra-exhausted` quarantine — a silent competence→reliability misrouting that loses landed work in exactly the subject domain this system runs.
3. **W3 — no dead-key memory across turns/runs** (turn.mjs:186-194): the hash-stable pick re-lands every infra-retry on the same key the previous turn already proved dead; the system burns full turns and upstream calls on known-bad keys and relies on a human to swap the secret. (Bounded by INFRA_RETRY_MAX=3 — not a livelock — but self-heal is absent where the telemetry to drive it is already in the journal.)
