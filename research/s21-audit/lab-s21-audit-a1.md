### Elaboration — C-1 (the BLOCKING)

Walk: wide epoch → main ladder saturates (403+Retry-After exhaustion, conductor-core.mjs:868-872) → `workerOverflowDecision` → repo2 dispatch on the PAT (turn.mjs:405) → the ONLY run for that task lives in agentrunners/fsm-lab-workers. Main's scan (`turn.mjs:275`, path from `verifyScanRunsPath(REPO, …)`, conductor-core.mjs:194-200) lists main's worker.yml runs → key `${id}#a${n}` absent → 720 s after lease issue, `dispatchVerificationEvents` (conductor-core.mjs:233-243) emits the synthetic `infra_failed 'dispatch-unverified'` REPORT → infra_attempts++ (fsm.mjs:293-305) → requeue+re-dispatch (possibly to repo2 again, while the first mirror worker still grinds — cross-repo supersession is impossible, worker.yml:53-59) → after 3 cycles the task is quarantined `infra-exhausted` and the real work's eventual report is an orphan. The lane that exists to ADD capacity instead destroys its own tasks. X26 (the planned live concurrent-overflow drill) walks straight into this.

Mitigating interaction: C-2's double-dispatch masks C-1 in the both-buckets shape (the main run exists → key seen → no flip) — the two bugs cover for each other, which is why neither has bitten live yet (epochs so far stayed at in-flight ≤1). Fixing C-2 alone will EXPOSE C-1; they must land together.

### Elaboration — the dispatch-ladder fence question (from the brief)

`max_parallel=4` IS CAS-safe, but not because of tick_min_interval_s/dedup_window: the real fence is (a) conductor.yml's `concurrency: group: fsm-conductor, cancel-in-progress: false` (conductor.yml:44-46) — single turn at a time per repo, and (b) the single-writer mutate: assignments happen inside `store.commit`'s CAS loop (turn.mjs:292-309; store.mjs:224-333, 6 jittered attempts, non-FF → re-read+re-apply) against the committed state, and workers never write state. `tick_min_interval_s=25` is a PACING sleep (turn.mjs:586-591), and `dedup_window=300` dedups REPORT event ids (fsm.mjs:184-193) — neither fences ticks (two different ticks mint different ids, event-ingest.mjs:81). The residual GHA-layer race is the pending-run replacement (C-4). The `WORKER_OVERFLOW_AT=1` live var additionally means the occupancy arm fires on the 2nd+ dispatch of ANY multi-assign tick — see C-2.

## §3 The 3 findings that most block production-grade

1. **C-1 (BLOCKING)** — the law-4 run-verification scan reads only main-repo runs, so every second-bucket dispatch is invisible: repo2-worked tasks flip to `dispatch-unverified` at 12 min, churn through the infra ladder, and get quarantined while their work is live (conductor-core.mjs:194-200 / turn.mjs:275 / conductor-core.mjs:233-244). The overflow lane — the capacity multiplier — is unusable as merged; X26 will prove it the hard way.
2. **C-2 (MAJOR)** — the in-flight overflow signal dispatches the SAME payload to BOTH buckets (main ladder already 204'd before the re-target): silent double work, 2× key burn on cc epochs, orphan-report noise — live-exposed by WORKER_OVERFLOW_AT=1 on any wide epoch (turn.mjs:388/399-405, conductor-core.mjs:826-828).
3. **C-3 (MAJOR)** — the straggler re-pause race (window re-populated by in-flight grinds racing the resume) remains unfixed and live-observed 3×; every operator resume can be followed by a false re-park, training operators to distrust the budget alert (conductor-core.mjs:560-564/574-609, fsm.mjs:365, EVIDENCE.md:398-414).

## §5 Focus questions (the brief) — one-line answers

- **Dispatch ladder / max_parallel CAS-safety:** safe via the GHA concurrency group + single-writer CAS mutate; 25 s/300 s are pacing/noise controls, NOT fences (see §2 elaboration). Residual: pending-run replacement (C-4).
- **workerOverflowDecision boundary:** correct arithmetic (`>=`, current dispatch excluded, conductor-core.mjs:836-842) but the in-flight arm double-dispatches (C-2); cannot starve the mirror (main stays primary); a dead PAT on a repo2-only dispatch → law-4 churn → quarantine in ~36 min with alerts (misclassified, C-1).
- **Straggler race:** NOT fixed anywhere; trigger gates lack any in-flight-cohort condition (C-3).
- **Lease expiry path:** conductor clock pass reaps (fsm.mjs:490-503) on the next tick after expiry; idempotent (state-based); CANNOT reap a live worker under the designed envelope (self-reap at deadline−2 min), but DOES under `lease_minutes:4` bootstrap epochs (C-5); reaping is suspended while paused (fsm.mjs:485-487) and heals on resume.
- **Tick economics:** quiesce = no commit/no API (store fetch only), quiet-tick zero-API verify guard; a held chain still burns ~6 backstop + 4 pinger runner-spins/h (free on public repos; X24 markers commit 4×/h, C-11). Chain-halted wake = backstop cron (sparse ~2 h observed) + pinger (15 min) + watchdog re-prime (scan.mjs:370-382, latch at :351-368).
- **Halted-vs-paused:** into halted = phase-done/degraded/milestone-unusable/operator halt; out = reset, unhalt (rejected on done, fsm.mjs:346), intake rollover (fires on ANY wake incl. backstop, conductor-core.mjs:622). Into paused = operator pause / budget pause; out = resume ONLY — no TTL, no re-alert (C-6) — the one permanent-wedge-shaped path. No wedge found that lacks either a wake or an alert except C-6/C-7.
